1. Show an agent’s steps, but don’t keep doing it forever.

(peer-reviewed — CHI 2026)

A CHI 2026 study of an in-car voice assistant finds that showing planned steps and intermediate results — not just a final answer — raises perceived speed, trust, and user experience while lowering task load, consistently across task complexity and context.

But interviewed afterward, nobody asked for permanently verbose feedback: people wanted heavy disclosure up front to establish trust, tapering off as the system proves itself reliable, adjusted by how much is at stake — a schedule a progress-display surface should follow, not a fixed amount of status.

2. Anthropic just gave agent interfaces a first-party “progress update” channel, separate from reasoning.

(vendor-primary — Claude Platform docs)

Anthropic’s Claude API now supports a dedicated progress-update content block — a short note on what the model just found and what it’s doing next, written explicitly for the person watching rather than as internal reasoning — now returns as its own signed block, distinct from any reasoning the model produces. A new display mode lets a product keep reasoning hidden entirely while still surfacing a live status line at each step.

This formalizes, as a shipped primitive, exactly the surface practitioners have been improvising around lately; agent-UI builders no longer need to parse a reasoning trace for progress cues.

3. A measurement rubric for “distracting” voice interfaces: 144 drivers, six systems, pupil diameter and heart-rate variability — and it’s still sitting in federal review.

(regulatory-primary — U.S. federal docket)

A U.S. federal information-collection request lays out exactly how voice-command-interface distraction in cars will be judged: 24 participants each across six systems including Android Auto, Apple CarPlay and Google Built-In, with cognitive workload read from pupil diameter, heart-rate variability, and a tactile detection response task — not a usability survey. As of a status check run today, the request has sat in regulatory review for 88 days with no control number yet assigned.

For anyone designing a voice interface for a car, this is the measurement stack a regulator will actually use, published well before any rule exists — worth designing against now, not after.

4. A phone-sized AI drafter can speed up generation 2–4x on just 5 megabytes of memory, and barely loses anything when squeezed to 4-bit weights.

(single-source — arXiv preprint)

HyFlash, a new on-device speculative-decoding method, fits its entire working memory into a fixed 5 MiB budget and beats a comparable prior method at every model size tested — roughly 2.1–2.6x speedup against 1.9–2.2x. Quantizing the drafter itself down to 4-bit weights keeps 99.2% of the speedup it had at full precision.

A specific, dated memory-and-latency budget for anyone trying to make an assistant run faster entirely on-device rather than leaning on a server round-trip — the kind of number that goes stale in weeks, which is exactly why it’s worth capturing now.

5. Carrying a user’s learned preferences across a model upgrade can now cost 38 minutes of overnight charging instead of a labeled-retraining pipeline.

(single-source — arXiv preprint)

Heirloom migrates a phone’s personalization settings to a new base model using only the user’s existing, unlabeled interaction history, losing at most 1.7 percentage points of accuracy compared with retraining on properly labeled data. For a 4-billion-parameter upgrade, the whole migration takes 38 minutes and about a fifth of the battery — well within an overnight charge.

A concrete feasibility number for a problem every on-device personalization feature eventually hits: what happens to what the system learned about you when the model underneath it changes.

Yesterday’s dossier

Yesterday’s dossier corrected the digest’s #1 item (Sidekick, UIST 2026): the study actually ran four conditions, not three, and the headline Sidekick-versus-chat comparison on total score is only a marginal trend (p = .079), not the significant result the digest attached to it. “No significant trust difference” overclaims too — the paper never ran a significance test on trust at all.

What does hold up: Sidekick’s one real, significant gain is a spreadsheet sub-score and error count, scored by a rule the authors built and calibrated themselves, against errors the agent was prompted to inject — and only Sidekick carried a built-in automatic-pause-on-error subsystem the paper’s own limitations section never names, so none of its three claimed “communication mechanisms” is actually isolated from that capability difference. Read against the corpus, this is a fourth measurement of “does showing the agent’s process help?” landing where three prior studies already did: null-to-trend against a plain chat baseline.
