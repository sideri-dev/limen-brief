1. A UIST 2026 study finds the agent-UI architecture that improves multitasking is three things together — ambient cue, resumption summary, verbalized reasoning — and it doesn’t buy more trust.

(peer-reviewed — ACM UIST 2026)

Thirty participants using Sidekick cut spreadsheet errors to 1.31 against 2.51 for a chat-only agent and 2.32 for ambient-text-only feedback, and scored higher on multitasking than either baseline (all p ≤ .001). People felt more able to intervene — but trust didn’t move across any condition.

Peer-reviewed, from this week’s conference: visible reasoning changes performance and interruptibility, not confidence in the system.

2. A 275-clinician study finds trust in medical AI runs on how the interface behaves socially, not on the accuracy it claims.

(single-source — arXiv preprint)

Interface familiarity, visible team consensus, and explainability each moved stated trust far more than disclosed accuracy — by the study’s own accounting, process cues carried roughly four-fifths of the total effect, accuracy a fifth. The paper opens by naming the assumption it tests against: that accuracy and outcome data usually drive trust in automation.

The design lesson for clinician-facing tools: spend effort on legible process, not a bigger accuracy disclosure.

3. A new auditing method shows an agent’s stored memory, on its own, can swing which sources it cites by up to 39 points.

(single-source — arXiv preprint, submitted Nov 2 2026)

Holding the question and search results fixed and varying only what the agent remembered about the user, one researcher found memory favoring a publisher raised that publisher’s odds of landing among the top three cited sources by 33-39 points, and memory expressing distrust of mainstream media raised citation of misinformation sources by 6.3 points — 3,000 trials, six models, two providers.

The case: let people see, and clear, the memory feeding a given answer. Citation isn’t neutral once memory is in the loop.

4. A GitHub Next designer argues the standard way agents show their plan is built for the agent, not the person reading it — and two shipped prototypes try to fix that.

(named practitioner — Maggie Appleton, GitHub Next)

Maggie Appleton’s case: a shared plan document that a human and an agent both “read” is really two different objects wearing the same file extension, and that mismatch is why plan review feels unsatisfying.

Chopin, a multiplayer planning editor, and Mindwalk, a visualization of the files an agent actually touched, are her lab’s attempt at interfaces built for how each party actually perceives a plan, not a text file both sides only pretend to read the same way.

5. Granola’s own account of designing its meeting-AI agent picks breadth with visible gaps over depth with false confidence.

(vendor-primary, single-source — Granola blog)

Rather than reading a full meeting transcript (10x the tokens) or pulling every piece of available context per query, Granola reads shallowly across all of a user’s meetings and shows “Coverage Notes” — what it actually looked at — instead of a confidence score it admits isn’t always warranted.

A shipped alternative to the single confident answer: show the gaps instead of hiding them.

Yesterday’s dossier

A follow-up dossier corrected the Memory Trap paper (yesterday’s #1): “worsens with the strongest models” overstates it — the gain is within model family, and the strongest model tested barely moves (0.18→0.19). What holds up and matters more: every text-level fix the authors tried is dead — scope audits of a memory note don’t predict unsafe behavior, diluting bad notes with benign ones doesn’t remove the effect, keyword detection misses the masking twice.

The same mechanism was measured once before, nine years ago, in Android’s ask-on-first-use permission grants. The conclusion: an instruction crossing from a layer that’s explicitly non-authoritative (memory) into one that treats it as authoritative (the agent) — a permission-layer problem, not a chat-interface one.
